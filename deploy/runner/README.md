# Серверный выпуск ресурсов

Штатный workflow `Release Design Tokens` выполняется на собственном CI-сервере. GitHub хранит очередь, секреты и результаты; оплачиваемые облачные исполнители GitHub для выпуска не используются.

Исполнитель `timeweb-design` зарегистрирован только для репозитория библиотеки с метками `self-hosted`, `Linux`, `X64`, `design-build`. Служба `design-actions-runner.service` работает от отдельного пользователя `design-actions` в `/var/lib/101-design-actions/runner`, без sudo и доступа к настройкам сайта, его рабочим каталогам, уведомлениям и исполнителю локализации.

## Ограничения

- Служба входит в существующую `system-frontendci.slice`, использует не более одного ядра и 3 ГиБ памяти; мягкий порог памяти — 2 ГиБ. Приоритет процессора и диска ниже работающего сайта.
- Выпуски выполняются последовательно через общую группу `design-tokens-release`. Время задания ограничено 30 минутами.
- Рабочая ветка — `main`; запуск по pull request не включён. Секрет `NPM_TOKEN` передаётся только шагам проверки доступа и публикации.
- Проверяются SVG, токены, iOS, Android и содержимое npm-пакета. Проверки перед созданием тега и публикацией не пропускаются.
- Java `17.0.21+9` загружается из официального репозитория Temurin с проверкой SHA-256. Автоматический опрос всех выпусков Java не используется: этот шаг зависал при серверном выпуске.
- Gradle использует локальный кэш выделенного пользователя; удалённый кэш GitHub отключён. Кэш программы исполнителя и его рабочий каталог не содержат скопированных учётных данных других исполнителей.

## Подключение и восстановление

Для SSH использовать уже проверенный административный доступ к CI-серверу из личных настроек оператора. Ошибка стандартного ключа сама по себе не означает отсутствия доступа. Закрытые ключи, токены и настройки конкретного Mac в репозитории не хранить.

Программа исполнителя берётся из официальной поставки GitHub Actions, уже установленной для локализации. Копируются только `bin`, `externals` и стартовые сценарии; `.runner`, `.credentials`, `.credentials_rsaparams` и регистрация другого исполнителя не копируются. Регистрационный токен нового исполнителя передаётся через стандартный ввод без вывода в журнал.

После регистрации установить соседний файл службы в `/etc/systemd/system/`, проверить через `systemd-analyze verify`, затем включить `design-actions-runner.service`. Не перезапускать сайт и не прерывать другие задания CI.

## Проверка выпуска

1. Проверить, что workflow использует метку `design-build`, а исполнитель `timeweb-design` находится в состоянии `online`.
2. При зависании в очереди проверить `systemctl status design-actions-runner.service` и журнал этой службы; не переключать задание на облачный исполнитель GitHub.
3. Дождаться успешного завершения точного коммита workflow.
4. Сверить числовой Git-тег, версию npm и `designTokensSourceCommit` опубликованного пакета. Только после этого устанавливать точную версию в потребителе.

Сообщение об оплате или лимитах облачных исполнителей GitHub относится к старому облачному запуску. Оно не доказывает блокировку штатного серверного выпуска; проверять реальный исполнитель и журнал конкретного задания.
